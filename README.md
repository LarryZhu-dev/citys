# 万城纪 · Empires at Dawn

原创美术的中文等距城建游戏。2.2 使用 **Godot 4.6.3 Web** 渲染世界、组件建筑、人物与 HUD，沿用 JavaScript 经济和 Node.js 在线服务。新建城市暂只开放华夏；其他地区显示「暂未开放」。

研究参考《模拟帝国》的城市层次与经营规则，没有提取原作美术。参考、具体实现和已知差距见 [Godot 实现](docs/GODOT.md)、[美术方向](docs/ART-DIRECTION.md) 与 [数值说明](docs/TIMING.md)。不以换引擎或自动测试通过代替商业品质验收。

本轮以用户上传的实际华夏城市截图重新分析并制作建筑构件、人物与车马，见[画面拆解](docs/REFERENCE-VISUAL-2026-10-20.md)。人物与车马的原图细节不足，相关新图是原创补齐，并非原版素材提取。

## 运行

```sh
npm ci
npm start
```

需要 Node.js 22.9 或以上，打开 `http://localhost:3000`。仓库包含 Godot Web 导出产物，不必安装编辑器即可游玩；浏览器需要 WebAssembly 和 WebGL 2。首次载入需下载引擎与资源包。

本地服务器同时提供真实账号、云存、参观、排行和交易，开发数据保存在 `work/local-online.json`。Vercel 生产环境使用 PostgreSQL，见 [DEPLOYMENT.md](DEPLOYMENT.md)。请通过 HTTP 访问，不能直接双击 HTML。

修改 GDScript 或 Godot 美术后需重新导出：

```sh
npm run engine:export
npm run build
```

引擎与官方模板版本固定为 4.6.3，安装位置见 [docs/GODOT.md](docs/GODOT.md)。构建校验导出物的 SHA-256，排除未使用的原始生图。编辑器单独运行场景不会连接浏览器中的经济，当前交付目标是 Web。

## 内容与操作

- 64×64 种子地图，噪声生成草土、河湖、林地和不规则矿脉。
- 华夏 42 类非道路建筑、道路、10 级普通住宅、6 级高级住宅；六章目标与终极奇观。
- 建筑由 96 张新绘制的石作、柱梁、墙窗、椽条、瓦排、檐脊、器物及枝叶图片逐件拼装；施工与完工使用同一批构件，没有整栋、整间房或整顶图片的替换。曲檐厅堂、八角宝塔、院落和五类店铺分别组织构件。
- 施工工人使用新绘身体部件生成的 192 张四向动作帧；市民及车马另有 225 张图集资源，包含独立车轮和马匹步态。工人按真实工期搬料、安装、上下梯和离场，工地夜灯与临时设施在完工后撤走。
- 构件按重要程度和体量分配施工时段，到安装时整件出现；地图直接显示施工剩余时间。升级保留未变构件，需要替换的部分先拆后建。
- 分材质月光、独立窗孔发光蒙版与炉口暖光；取水人、补货商贩和马车按真实任务行走，货物入库才可使用。
- 道路随相邻建成住宅与美化分为土路、石子路、石板路；连通矿区生成连续岩体。
- 48 个原创资源/操作图标和四套九切 HUD 面板。
- 建设持续分钟到小时，华夏奇观约 30 小时；生产每批 5–30 分钟。自由营造提供 1/4/60 倍，征程按真实时间运行。
- 离线自动经营最多结算 8 小时，已有施工最多推进 72 小时；重复读档不会重复发放时间收益。
- 自动存档、三个手动槽、JSON 导入导出、切城备份和旧档迁移。旧文明数据保留，新美术和首发平衡专注华夏。
- 真实账号、版本化云存、只读城市参观、繁荣榜、物资托管与原子交易，另有单机商队。

底部「营造」选建筑，再点地图放置；「修路」可拖动铺设。点击建筑查看需求、迁移或拆除。空白处拖动平移，滚轮或双指捏合缩放。顶部查看库存与城志；「视野」切换昼夜、覆盖层和舆图；「城务」包含档案、设置和帮助。手机横竖屏分别排布，常驻 HUD 留出主要地图空间。

起步先修水井、增加住宅，再安排粮食和木材。服务和生产设施需要道路与工人；同类早期商铺隔路成对，中央集市可整合配送。住宅满足下一等级需求、入住率达到 90% 并持续稳定 10 分钟后，点击建筑详情中的升级按钮，投入材料并开始施工。初始城镇货栈提供基础仓储；新建粮仓或仓库后，运输优先使用适合的库房。

暂停和在线事务窗口会冻结当前经济并更新时钟水位；关闭页面后的离线规则另行结算。在线市场属于休闲社区：客户端负责模拟，服务端防止重复成交和版本覆盖，但排行榜不保证竞技公平。本次联网范围不含实时共同建城或战争。

## 验证

```sh
npm test
npm run build
npm run test:godot
npm run test:browser
npm run test:input
npm run test:revision
npm run test:performance
```

`npm test` 包含真实 Godot 构件与施工工人测试，需要 PATH 中的 Godot 4.6.3，或通过 `GODOT_BIN` 指定可执行文件。测试会导入实际图片，不能只靠 Node.js 运行完整套件；游玩已导出的游戏与 Vercel 构建不要求安装 Godot。

浏览器验收默认使用系统 Chromium，可设置 `CHROMIUM_PATH`；测试使用临时账号数据库。`test:godot`（亦即 `test:visual`）检查真正的 Godot Web 场景、桌面/手机横竖屏、触摸建造、拖动、捏合和存档。`test:browser` 检查两账号的云存、参观、排行、交易与丢响应恢复；`test:revision` 检查实际手动升级、施工工人移动与暂停、货物运输和重载。

`test:performance` 在实际导出包中载入范例城市，记录日夜、拖动与暂停的浏览器帧间隔和引擎绘制提交数。默认使用 SwiftShader；有 X 显示服务时可设置 `CHROMIUM_ANGLE_BACKEND=gl` 对照系统 OpenGL，并用 `PERFORMANCE_OUTPUT` 分别保存结果。报告包含浏览器实际 GPU 名称和资源包摘要，不能仅凭后端名判断是否使用硬件。图形测试应串行运行，避免争用同一 GPU；软件 GPU 结果不代表手机真机帧率。

自然预算的完整通关路线约 **58 小时 32 分钟模拟时间**，人口 616；没有添加资源跳过经济；测试路线在升级条件满足时调用与按钮相同的手动升级指令。这证明目标可达，不代表玩家普遍完成时长。可导入 [范例城市](examples/completed-city.json) 检查布局与建筑，范例不是在线玩家。

具体测试结果、软件 GPU 性能及尚未完成的生产/真机验收见 [VALIDATION.md](VALIDATION.md)。原始生图、提示词及处理工具保存在 `godot/art/*/sources/`，不导入运行包。旧建筑图集、旧整栋素材及旧 Canvas 绘制代码已删除；历史版本可通过 Git 追溯。
