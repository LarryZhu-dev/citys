# Godot Web 实测与世界实现状态

2026-10-20。世界渲染/输入代码现已冻结；正式工程没有分层调试开关，开关仅存在于 `profile-project/` 测试副本。根代理之后增加的灯光合成与最终桥接行为仍需正式导出复测。

## 实际结论

Godot 初版最重的固定开销已显著降低：同一个通关城市、同一浏览器环境，全层日景从约0.69 FPS提高到7.88 FPS，建筑draw call从约3006降低到344。但这仍是**明显卡顿，尚未通过流畅性验收**。不应把引擎迁移、原生断言通过或提交时间减少等同于手机60 FPS。

测试环境：Chromium154.0.8037.57，1440×900 CSS像素，DPR1，ANGLE/Vulkan SwiftShader软件GPU，容器5逻辑CPU。没有真实GPU或真机性能证据。第三轮测试前确认没有其它Chrome/Godot图形进程。每个静态阶段预热约1.8秒，再采样约4秒；样本较短，属于定位性测试而非长期稳定性认证。

固定城市：`work/completed-city-realtime.json`，seed=`campaign-integration`，268建筑记录（包括道路），616人口，1322自然资源簇。初始可见区相机、CSS缩放保持一致。浏览器首次ready耗时8.315秒，第三轮没有console/page errors。

## 已实施的结构改变

- 世界格128×64，Camera2D缩放只改变变换，完全移除Canvas每zoom档的同步像素块缓存生成。
- 地表是世界坐标GPU shader。低频草土场预存入64×64 mask，细节采样单张可重复噪声纹理；常规地表2次纹理采样，low设置1次。水像素单独计算窄岸线/波纹。
- 道路拓扑变化时构造共享ArrayMesh，常规一笔提交；覆盖层使用64×64 mask，只在输入改变时生成。
- 槐、松、柳、竹为新生图资产，真实透明边缘、校准树干地面锚点；矿树有确定性分簇偏移。自然资源共用一张GPU图集，透明y-sort容器与建筑共用真实地面深度。
- 四方向×四帧中国工匠新生图；共用图集，人物ID与路径跨快照持久，BFS在派发路线时运行，帧只推进连续位置。最多80人，low24人。
- CSS归一相机与输入阈值；真实双指中点保持、触摸与GUI仿真鼠标去重、GUI接管release后清理手势状态；批量正交道路补点，手势之间不串线；迁移预览忽略自身id。
- quality设置实际改变树/矿数量、行人上限和细节采样；reducedMotion/暂停冻结装饰时钟而不改变经济钟。
- 建筑代理将数万即时图元改成每模块缓存ArrayMesh，并将建筑纹理并入共享atlas。

## 仍未解决的验证与预算问题

1. 软件GPU上常规场景仍只有约8 FPS。虽然不代表真实硬件，但已证明目前不能声称“验证流畅”。数百建筑提交及高分辨率WebGL填充仍需硬件性能验证或继续压缩预算。
2. 连续pinch后即使zoom回到原值，所测暂停阶段仍只有3.71 FPS；这段退化未得到充分归因，需正式包更长GPU/浏览器trace或真实设备重现。
3. 暂停冻结动画，但`OS.low_processor_usage_mode`没有让Web端真正静态停帧；主/HUD同步与呈现调度仍需根节点统一处理。不能把当前暂停作为省电完成。
4. 本次原始Canvas调查使用初始小城和435住宅压力fixture；Godot测试使用268记录的合法通关城市。**两者不能直接用FPS相除来宣称迁移优于Canvas。** 可比较的是Godot相同fixture优化前后。
5. 移动原生HUD触摸、道路批量桥接、最终灯光修复、在线多账号流程由根代理/对应代理在正式导出上验收；本报告不把它们提前记为通过。
